# Beta Test Accounts And Permissions

## 1. 관리자 테스트 계정 개념

현재 Beta MVP는 실제 로그인/회원가입 시스템이 아니라 간이 role 기반 구조를 사용한다. 관리자 화면은 `/admin`이며, 관리자 전용 API는 `x-user-role: admin` 헤더를 기준으로 보호한다.

관리자 테스트 담당자는 다음 기능을 검수한다.

- AI 상태 점검
- 라이더 위험도 요약
- 분석 근거 보기
- AI 코칭 생성
- 발송 대기함 관리
- 운영 로그 보기
- AI 운영본부 브리핑 생성
- 백업/복원
- 베타 테스트 준비 상태 확인

## 2. 라이더 테스트 계정 개념

라이더 화면은 `/rider`이며, 베타 단계에서는 사전 로그인 전 테스트 화면 성격이다. 라이더 선택 또는 테스트 대상 라이더 기준으로 본인에게 공개 가능한 정보만 확인한다.

## 3. 관리자 화면에서 가능한 기능

- AI 코칭 생성/재생성
- 관리자 내부 코칭 이력 확인
- 관리자 액션 체크리스트 변경
- 데이터 검수 경고 확인
- 분석 근거 및 AI 입력값 미리보기
- 카톡/문자 발송용 문구 복사
- 발송 대기함 추가/수정/삭제/발송완료 처리
- 주간 브리핑, 월간 리포트, AI 운영본부 브리핑 생성
- 운영 로그 확인
- 운영 데이터 백업/복원

## 4. 라이더 화면에서 가능한 기능

- 본인 주간 요약 확인
- 본인에게 공개 가능한 코칭 메시지 확인
- 본인 성과/정산 관련 안내 확인
- 모바일 화면 가독성 확인

## 5. 라이더 화면에 노출되면 안 되는 정보

- 운영 로그
- 발송 대기함
- 발송 이력
- AI 운영본부 브리핑
- 분석 근거 보기
- AI 입력값 미리보기
- 관리자 액션 체크리스트
- 관리자 내부 메모
- 백업/복원
- 운영 준비 점검
- 다른 라이더의 상세 데이터

## 6. 테스트 전 확인해야 할 권한 항목

1. `/admin`에서 관리자 전용 패널이 보이는지 확인한다.
2. `/rider`에서 관리자 전용 패널이 보이지 않는지 확인한다.
3. 운영 로그와 발송 대기함이 `/rider`에 노출되지 않는지 확인한다.
4. 관리자 API 직접 호출은 `x-user-role: admin` 헤더가 필요함을 확인한다.
5. 라이더 API는 다른 라이더 데이터 접근이 제한되는지 확인한다.

## 7. 운영 로그와 개인정보 주의사항

- 운영 로그에는 관리자 작업 내역이 남는다.
- 실제 전화번호, 민감한 정산 정보, 개인 식별 정보는 테스트 로그나 버그 리포트에 그대로 적지 않는다.
- 스크린샷 공유 전 라이더 이름과 식별 정보 노출 범위를 확인한다.
- 외부 베타 URL은 제한된 테스터에게만 공유한다.
