# 모바일 우선 관리자 대시보드 원칙

새 주차 업로드 직후 관리자 첫 화면은 상세 통계보다 운영 판단을 먼저 보여준다.

## 우선순위

1. 업로드된 최신 주차와 데이터 신뢰도
2. 정상 분석 건수, 오류/확인 필요 건수, 신규 자동 분석 대상 라이더 수
3. 전주 대비 핵심 변화 3개
4. 즉시 조치가 필요한 시간대
5. 런치 미션 후보와 예상 예산
6. 데이터 검수, 미션, 코칭 바로가기
7. 상세 통계와 긴 리스트는 하단에 배치

## 관리자와 라이더 화면 구분

관리자 화면에는 전체 주차 브리핑, 검수 상태, 미션 예산 후보, 조치 필요 구간을 표시할 수 있다.

라이더 화면에는 관리자 메모, 전체 비교표, 미션 예산, 내부 조치 필요 구간을 표시하지 않는다. 라이더에게는 본인 기준 주차, 본인 코칭 메시지, 본인 실천 미션만 보여준다.

## 계산 기준

- 최신 주차는 업로드 목록의 weekKey를 기준으로 계산한다.
- 핵심 변화는 최신 주차와 직전 주차의 완료건수, 운행 라이더 수, 주요 시간대 완료건수를 비교한다.
- 런치 미션 후보는 최신 주차의 Lunch_Peak 완료건수를 기준으로 10건 이상, 14건 이상 후보를 나눈다.
- 예상 예산은 14건 이상 후보에게 상위 조건 1회 지급을 우선 적용한다.

## 운영 메모

`backend/src/data/parsed`, 업로드 원본, 엑셀/CSV 원본, 개인정보 가능 데이터는 문서나 Git에 포함하지 않는다. 브리핑 화면은 API가 계산한 집계 결과만 표시한다.
