# 엑셀 업로드 가이드

라이더 코칭센터는 쿠팡이츠 주차별 상세 엑셀의 컬럼명이 조금 달라도 업로드를 시도합니다. 베타 테스트 전에는 아래 기준으로 샘플 엑셀을 먼저 검수해 주세요.

## 권장 컬럼명

- 라이더명: `라이더명`
- 완료건수: `완료건수`
- 배달타입: `배달타입`
- 시간대: `피크타임` 또는 `해당 구간타임`
- 픽업/배달 지역: `픽업지역`, `배달지역`
- 시간: `수락시간`, `배달시간`, `배달소요시간`

## 라이더명 컬럼 후보

`라이더명`, `기사명`, `배달파트너명`, `배달파트너`, `파트너명`, `이름`, `수행자`, `배달원명`, `배달원`, `라이더`, `기사`, `riderName`, `rider_name`, `driverName`, `driver_name`, `courierName`, `courier_name`

컬럼명 앞뒤 공백, 대소문자, 괄호나 특수문자 차이는 최대한 무시해서 인식합니다.

## 완료건수 컬럼 후보

`완료건수`, `수행건수`, `배달완료`, `완료 수`, `완료수`, `주문수`, `처리건수`, `건수`, `completed`, `completedCount`, `complete_count`, `deliveryCount`, `delivery_count`

완료건수가 없으면 기존 상세 행 규칙대로 1개 행을 1건으로 처리합니다. 값이 숫자로 변환되지 않으면 업로드는 계속 진행하고 데이터 검수에 숫자 변환 경고를 남깁니다.

## 배달타입 컬럼 후보

권장 컬럼명은 `배달타입`입니다. `배달 유형`도 인식합니다.

## 배달타입 허용 예시

- 단건: `단건`, `단건배달`, `단건 배달`, `단일`, `일반`, `일반배달`, `1건`, `SINGLE`, `single`, `Single`
- 멀티: `멀티`, `멀티배달`, `멀티 배달`, `멀티1`, `멀티 1`, `멀티배달1`, `멀티배달 1`, `멀티2`, `멀티3`, `멀티4`, `M1`, `M2`, `M3`, `M4`, `multi`, `MULTI`, `Multi`
- 숫자: `2`, `3`, `4`는 각각 `멀티배달2~4`로 처리합니다. 숫자 `1`은 단건/멀티 여부가 불명확하므로 `확인필요`로 둡니다.

## `확인필요`의 의미

`확인필요`는 업로드 실패가 아닙니다. 완료건수 집계에는 포함하지만, 배달타입 분석에서는 별도 분류하고 관리자 데이터 검수 화면에 원본값과 행 번호를 남깁니다.

빈 값, `null`, `undefined`, `-`, `N/A`, `없음`, 또는 해석할 수 없는 값은 `확인필요`로 처리합니다.

## 오류 확인 방법

1. `/upload`에서 파일을 선택하고 `파싱 미리보기`를 실행합니다.
2. 업로드 결과 요약에서 총 행 수, 정상 파싱 행 수, 라이더명 인식/누락 행 수, 배달타입 정상/확인필요 행 수, 숫자 변환 경고 행 수를 확인합니다.
3. `/validation`에서 같은 주차를 선택합니다.
4. 검수 경고 요약에서 동일 오류가 그룹화되어 표시되는지 확인합니다.
5. 상세보기를 열어 행 번호와 원본값을 확인합니다. 상세 행은 그룹별 상위 30개까지만 표시됩니다.

## 베타 테스트 전 샘플 검수

1. 실제 주차별 상세 엑셀 1개를 `/upload`에서 미리보기로 확인합니다.
2. 라이더명이 `미확인 라이더 #번호`로 과도하게 표시되면 라이더명 컬럼명을 확인합니다.
3. 배달타입 `확인필요`가 많으면 원본 배달타입 컬럼의 실제 값을 확인합니다.
4. 저장 후 `/admin`, `/validation`, `/analysis`, `/rider`를 확인합니다.
5. `/rider`에는 업로드 오류 상세, 운영 로그, 발송 대기함, provider/fallbackReason이 표시되지 않아야 합니다.

## 15차-1.5 parsed JSON 복구 절차

15차-1 파서 안정화 이후 기존 `backend/src/data/parsed` 데이터는 재생성이 필요할 수 있습니다. 배포본에서 `Unexpected non-whitespace character after JSON` 같은 JSON parse 오류가 보이면 기존 저장 데이터가 손상되었거나 구버전 parsed 결과일 가능성이 큽니다.

조치 순서:

1. `/validation`에서 `parsed 데이터 관리` 패널을 확인합니다.
2. `JSON 파싱 오류 N건 / 재파싱 필요`가 표시되면 상세보기에서 파일명, 주차, 오류 유형만 확인합니다.
3. `기존 parsed 데이터 초기화`를 눌러 parsed 결과 파일만 초기화합니다. 원본 업로드 임시 파일이나 운영 로그/메모/발송 대기함은 초기화 대상이 아닙니다.
4. 초기화 후 최신 쿠팡이츠 주차별 상세 엑셀을 `/upload`에서 다시 업로드합니다.
5. `/validation`, `/admin`, `/analysis`, `/rider` 순서로 표시 상태를 확인합니다.

베타 테스트 전에는 반드시 최신 엑셀을 다시 업로드해 새 파서 기준의 parsed JSON을 생성하세요. `/rider` 화면에는 parsed 오류 상세나 관리자 내부 검수 정보가 노출되지 않아야 합니다.
